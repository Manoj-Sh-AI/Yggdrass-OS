# Application connections before agents

2026-11-14. The owner requested a connected data foundation and authorized implementation before agents. Automatic creation is intended only for clear actionable interpretations; uncertainty asks. The revised timer policy is a single human-focus clock that hands off on intentional task focus changes, with independent unattended background clocks. Opening details alone is chosen not to move focus after the owner delegated that interaction choice.

Reuse current canonical application entities and typed local foreign keys. Add note references plus explicit task/note, event/note and event/task associations, background-run storage, a transactional append-only journal and a read-only operational edge view. Keep all of them in app; never change Brain DDL, copy note bodies or write semantic relationships. Cross-service identity is verified through the existing Brain reader, not an impossible cross-database foreign key.

The app's journal is not a fully event-sourced store or a delivery service. Database triggers make journal entries atomic for application writes, including legacy endpoints. Runtime cannot forge, update or delete journal rows; the trigger function has an explicitly fixed search path and qualified application-table references. Sequence allocation is not commit ordering. Future delivery needs consumer receipts, idempotency and reconciliation. Trusted data-only preview restores suppress triggers to preserve journal records without generating duplicate history; they use the existing isolated cluster administrator, never the runtime role.

The schema/backend foundation is staged and tested in isolated PostgreSQL. Do not activate live DDL as an implicit service-start side effect. Temporal interpretation fields, note-save delivery, commitment reconciliation and the operational Graph UI remain a subsequent contract/integration step. No model, worker, runner or orchestrator is built here. Current focus UI behavior is not changed by documenting the new handoff contract.
