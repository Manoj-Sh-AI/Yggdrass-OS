# Planning

How the spec gets built. Lifecycle step 2.

## Files

- `layers.md`: how interface, processing and data map to this project (fill in before coding)
- `librarian-plan.md`: the memory plan, the brain as an organised library with a librarian that reads a cached manual and opens only the notes it needs. It holds the evidence so far, the roadmap and the planned experiments
- `future-executive-layer.md`: **parked ideas, not decisions**: an always-on executive layer (calendar, tasks, reminders) and Lia's calls. Nothing here is built until the memory rung passes its hard eval
- `lia-and-connector.md`: **draft plan, nothing built**: adding knowledge from any chat app through a thin MCP connector and Lia, with button-first approval, a deterministic checker and Undo. Open decisions and draft pass bars are listed at its end
- Per-feature plans: `plan-<feature>.md`, written after the spec is approved

## Rule

Design the layers before coding. One page is enough.
