## The six maps, proposed formats

Formats are taken from the node-template and folder-structure research reports.

| Map | One line per | Proposed contents |
|---|---|---|
| `shelf-map.md` | note, grouped by folder | slug, type, area, `also`, status, review, description, aliases, updated, fact count. This would answer node.md's open question Q4 (extra columns) with yes |
| `atlas.md` | area and hub | folder, hub slug, note count, the hub's description as the scope, the hub's aliases |
| `alias-index.md` | alias | alias → slug, sorted, so a nickname resolves in one step |
| `active.md` | open item | active projects and goals, open decisions, and every review date, soonest first |
| `timeline.md` | dated note, by month | events (`date`), decisions (`decided`), journal entries (slug date) |
| `lint.md` | problem | parser errors, dangling links, unknown verbs, duplicate aliases, notes with no typed link, decisions with no review date, fact lines with no source, and a count of "Not recorded yet." sections per type |

## The review-date rule

The maps must be byte-identical for unchanged notes (D5). So:

- `active.md` lists every review date, soonest first, but does not judge "due" or "overdue", because that depends on today's date.
- The overdue check lives only in `lint.md`, and takes an explicit `--today` date that defaults to the run date. `lint.md` is therefore the one map whose output can change without the notes changing.
